# 广义五子棋与对抗搜索 实验报告

## 1. 总体设计

程序下在 `assignment1/`，对局规则和 AI 分开：规则层只负责落子、胜负与和棋，AI 只通过统一协议读棋盘并返回坐标。这样人人对战、人机对战、机机对战共用同一套判定，换对手时只更换实现了 `GomokuAI` 的文件。

```
assignment1/
├── main.py           # 无参数开图形界面，有参数进入命令行
├── gui.py            # 图形界面
├── main_cli.py       # 命令行三种模式，以及 --bench 实验
├── gomoku_game.py    # 棋盘、落子、K 连与和棋
├── gomoku_ai.py      # 评赛用 AI（文件名和类名按协议固定）
├── random_ai.py      # 随机合法落子，作为基线
├── test_basic.py     # 规则与必胜/必防的自测
├── requirements.txt
└── report.md
```

棋盘是 `N × N` 的方格，`0` 空、`1` 黑、`2` 白，坐标从 `(0, 0)` 开始。黑棋先行。横、竖、两条斜线上连续至少 `K` 子即胜，长于 `K` 的连珠同样算胜，没有禁手。下满仍没有 `K` 连则为和棋。`N` 和 `K` 只来自开局参数：图形界面里的设置，或命令行 `--board` 与 `--win`。AI 构造函数收到的 `board_size`、`win_length` 是搜索和评估里唯一的尺寸来源。

三种模式：

1. **人人**：双方轮流点击格子，或在命令行输入 `行 列`。
2. **人机**：人类执黑或执白，另一色为 `gomoku_ai.GomokuAI`。AI 在后台线程里思考，界面不会卡住。
3. **机机**：按同一接口加载两个 AI。界面里可选“自己对随机”或“自己对自己”；命令行可以用 `--ai1`、`--ai2` 指定任意协议文件，`--games` 大于 1 时交换先后手。

运行方式（在 `assignment1` 目录下）：

```bash
python main.py
python main.py --mode pvp --board 15 --win 5
python main.py --mode pve --board 15 --win 5 --human 1 --time 5
python main.py --mode eve --board 9 --win 4 --time 1 --games 2 --ai2 random_ai.py
python main.py --bench
python test_basic.py
```

课程裁判仍按原协议加载 `gomoku_ai.py`，例如：

```bash
python arena.py assignment1/gomoku_ai.py random_ai.py --board 15 --win 5
```

## 2. AI 算法说明

`GomokuAI.get_move` 每步都从裁判给出的棋盘重新建内部局面，不修改传入的棋盘，也不依赖上一局的记忆。核心是 **Minimax + Alpha-Beta**，外面套 **迭代加深**，用来在时限内留下一个已经搜完的着法。

### 2.1 搜索框架

终局分数记为 `WIN`（本程序取 `5_000_000`）。越早获胜分数越高（`WIN - 已走层数`），越早失败分数越低。和棋为 `0`。静态评估被限制在 `±900_000` 以内，因此它不会被当成已经证明的胜负。

```
function GET_MOVE(board, time_limit):
    deadline ← now + time_limit - reserve          # reserve 约为时限的 10%，且不超过 0.3 秒
    moves ← ORDERED_MOVES(自己)
    if moves 只有 1 个:                            # 开局天元，或唯一的取胜/必防点
        return moves[0]
    best ← moves[0]
    for depth = 1, 2, ...:
        if 上一层耗时 × 2 已经放不进剩余时间:
            break
        try:
            best ← ALPHA_BETA_ROOT(depth, deadline)
        catch 超时:
            break
        if 本层没有搜完所有根着法, 或已经证明胜/负:
            break
    return best

function MINIMAX(depth, α, β, to_move):
    if 刚下的子形成 ≥ K 连:
        return 对应的 ±(WIN - 层数)
    if 棋盘已满:
        return 0
    if depth = 0:
        return EVALUATE()                          # 从自己的角度看
    for move in ORDERED_MOVES(to_move):
        下子，递归，悔棋
        用 α、β 剪枝；发生剪枝时给该着法累加历史分
    return 该节点的值
```

根节点若有多个着法分数完全相同，则随机选一个。这只影响平分着法，搜索本身仍然决定分数。自对战因此不会每局都走出同一条棋。

### 2.2 评估函数

评估沿所有行、列、两条对角线扫描连续棋段。一段棋由长度 `length` 和开口数 `open_ends`（0、1 或 2）描述。开口数为 2 是活连，为 1 是眠连，为 0 是两端都被挡住或顶到棋盘边缘的死连，得 0 分。

分值不写死“五连”，而看离胜利还差几子 `gap = K - length`：

| 棋型 | 分数 |
| --- | ---: |
| 活的 `K-1`（再下一手就胜，且两端都能下） | 200000 |
| 眠的 `K-1` | 50000 |
| 活的 `K-2` | 2000 |
| 眠的 `K-2` | 200 |
| 活的 `K-3` | 200 |
| 眠的 `K-3` | 20 |
| 更短的活连 / 眠连 | 10 / 2 |

`K = 5` 时，活四高于眠四，眠四高于活三。`K = 3` 或 `K = 4` 时，同一张表会自动把“差一手”的棋型提到最高档。自己的分数相加，对方的分数按 1.1 倍扣除，同等棋型下略偏向先手防守。真正形成 `K` 连的局面在搜索里当终局处理，不靠评估函数判胜。

对比实验里还有一个故意做弱的“简单评估”：只按 `length²` 给连续棋段打分，不区分活连和死连。必胜和必防的着法生成两边相同，差别只在非强制局面的取值。

### 2.3 候选着法、排序与时限

空棋盘只产生中心点。否则只产生与任一已有棋子切比雪夫距离不超过 2 的空位，避免在 `15 × 15` 上展开两百多个空位。

排序与裁剪：

- 自己这一手能连成 `K`，只保留这一步。
- 否则若对方只有一个立即获胜点，只保留封堵那一点；若有两个以上，这些点都必败，只在它们之间搜索。
- 其余着法在根节点按“下在这里会形成的棋型 + 半份封堵价值 + 靠近中心”排序；深层节点用历史启发（剪枝着法加 `depth²`）和离上一手的距离排序。
- 非强制着法最多展开 12 个（`N ≤ 9` 时 14 个，`N ≤ 6` 时 30 个）。取胜点和必防点不受这个上限裁掉。

时限留出约 10% 的余量（最多 0.3 秒）。迭代加深若估计下一层来不及搜完，就不再开始那一层；层内超时则保留本层已经算完的根着法，否则退回上一层的结果。因此返回时间会低于 `time_limit`，而不是卡在裁判的墙钟上限上。

`N`、`K` 变了以后，候选范围、`gap` 分档、胜负判定和搜索深度上限都跟着构造参数走。小棋盘允许更深的层数，因为分支更小；真正停在哪一层仍由剩余时间决定。

## 3. 实验评估

实验由 `python main.py --bench` 复现。每局开始前设置不同的随机种子。思考时间是 `get_move` 的墙钟时间，只统计本方 AI。对随机 AI 的对局交换先后手，各 10 局。评赛默认时限是 5 秒；为了在本地跑完 20 局以上，对局实验用了更短的时限。第 3.4 节单独在一个固定中盘上把时限放到 5 秒。

随机 AI 很弱，所以对它的胜率主要说明“能稳定抓住必胜并挡住对方的连珠”。深度对比和评估函数对比更能说明搜索与启发的作用。

### 3.1 对随机 AI

| 配置 | 时限 | 局数 | 胜-负-和 | 胜率 | 平均手数 | 平均每步 | 平均完成深度 |
| --- | ---: | ---: | --- | ---: | ---: | ---: | ---: |
| 15×15，K=5 | 0.8s | 20 | 20-0-0 | 100% | 11.8 | 0.377s | 3.11 |
| 9×9，K=4 | 0.5s | 20 | 20-0-0 | 100% | 7.7 | 0.166s | 2.41 |

15×15 上先手 10 局、后手 10 局全部获胜。平均思考时间明显低于时限：很多步是唯一的取胜或必防，直接返回，不把预算用完。对局也很短，随机方挡不住连续威胁。

### 3.2 自对战

15×15、K=5、每步 0.6 秒、共 8 局：黑胜 5，白胜 3，和棋 0。平均手数 27.9，平均每步 0.314 秒。八局手数分别是 22、31、14、22、25、19、27、63。

先后手都有胜局，黑棋略多。在 0.6 秒的预算下，搜索还证明不了从开局开始的必胜，所以自对战会下到中盘，而不是固定的短胜。平分着法的随机选择让各局走法不同。

### 3.3 两组配置，以及深度、评估的对比

上一节已经比较了 `(15, 5)` 和 `(9, 4)`。小棋盘、较小的 `K` 上，随机对局更短（7.7 手对 11.8 手），因为更早出现致命的连珠；思考也更浅、更快。

在 11×11、K=5、每步最多 1.0 秒、交换先后手的 8 局里，把迭代加深分别限制在 2 层和 4 层：

- 深度 4 胜 6 局
- 深度 2 胜 2 局

更深的搜索更强，但深度 2 仍能靠必胜/必防和评估赢下 2 局，说明浅搜索不是完全不能下棋。

同一棋盘上，棋型评估对简单评估（8 局，每步 0.8 秒，交换先后手）：

- 棋型评估胜 6 局
- 简单评估胜 2 局

简单评估仍能赢，是因为它和棋型评估共用同一套取胜/封堵检测。差别出现在还没有立即胜负的局面：不分活连和死连时，会高估两端被挡住的棋，也会低估活三一类后续威胁。

### 3.4 时限与搜索规模

固定一个 15×15、K=5 的中盘（双方各 5 子，轮到黑棋），只改变时限：

| 时限 | 着法 | 完成深度 | 节点数 | 实际用时 |
| ---: | --- | ---: | ---: | ---: |
| 0.2s | (9, 8) | 4 | 736 | 0.073s |
| 0.5s | (5, 5) | 5 | 3119 | 0.303s |
| 1.0s | (9, 8) | 5 | 8512 | 0.904s |
| 2.0s | (9, 8) | 6 | 10490 | 1.039s |
| 5.0s | (9, 8) | 7 | 48979 | 4.063s |

时限放宽后，完成深度从 4 增到 7，节点数大致按层增加。5 秒预算下实际用了 4.06 秒，留在裁判时限之内。0.5 秒时根着法与其余时限不同，说明这一层的结果还不稳定；从 1 秒起着法一致为 `(9, 8)`。1 秒档的节点数高于“刚好搜完深度 5”所需，是因为程序又开始了更深的一层，但那一层没有搜完，对外仍报告最后一层完整结果。

## 4. 讨论与反思

实现里比较花时间的是时限和着法生成，而不是 Minimax 本身。纯 Python 在 15×15 上，5 秒大约能稳定完成 7 层左右（上表约 4.9 万个节点）。若对所有空位展开，或每个叶子都做很重的评估，会在更浅的层数上耗尽时间。把候选限制在棋子附近，并让迭代加深在来不及的时候停下来，比单纯把深度写死更稳妥。

评估函数的主要不足有三点：

- 它只认识连续棋段，不直接认识“中间空一格”的跳活，例如 `XX_XX`。这种棋要靠“下在空位是否立即获胜”的检测，以及至少两层的搜索才能看见。层数不够时，会漏掉再往后一步的双威胁。
- 水平线效应还在：刚好超出深度的威胁，只能靠评估的粗分，不能当证明。
- 距离现有棋子两格以外的空位被直接丢掉。安静的远手在五子棋里很少是好棋，但这个限制仍然是近似。

自对战在 0.6 秒下黑棋只是 5 比 3 领先，说明当前深度还远没有下出自由五子棋先手必胜的那种长被迫着。若继续做，优先加置换表，让迭代加深能复用上一层的结果；然后在评估里补上单缺口棋型，或做威胁空间搜索，专门追活四、冲四。蒙特卡罗树搜索可以在大棋盘上当另一条对比基线，但在 5 秒的纯 Python 预算里，不一定强过带棋型评估的 Alpha-Beta。

实验也有限度。对随机 AI 的 100% 胜率不能代表对同学 AI 的水平；深度和评估的对比各只有 8 局，6 比 2 这种差距方向清楚，但不是精确胜率。`--bench` 可以改局数后重跑。
